Origins, insertions, via points and wrapping

This is a map of the geometry actually used in the forward simulation. It distinguishes fixed bone/body attachments, moving routing points and wrap surfaces. The visible bone mesh does not automatically determine a muscle path. Some coordinates are registered or estimated model geometry, not measured feline attachment coordinates.

Which file do I edit?

  • attachments.py: body-fixed origin/insertion/via coordinates. The named body and role appear immediately above each entry. Metres: 0.001 m = 1 mm. Changing a point site's orientation alone does not move its centre or alter MT length.
  • routing.py: geometry parameters of computed moving via points and preferred wrap-side selectors. Their positions are recalculated from joint angles at each step; a static site-coordinate edit would be overwritten.
  • wrapping.py: centres, orientations and radii of the actual sphere/cylinder wrap objects. These are separate from the visible bone surfaces.
  • muscle_tendon.py: constant MT path offset, optimal fibre length and slack tendon length. Changing an attachment does not automatically change these parameters.

Run .\run_model.ps1 --parameters config/user_model --seconds 3 --output my_attachment_trial from the project folder. A new run rereads the files, applies the values before time zero, and writes an ATTACHMENT_MAP.html and APPLIED_PARAMETERS.json. Edits are not silently refitted. Use a new output name for each trial.

Where are these coordinates?

A local coordinate belongs to the named rigid body, not the world and not the bone mesh file. In a hindlimb thigh frame, zero is the hip centre and +x runs along the segment towards the knee. In shank and foot frames, zero is their proximal joint and +x points along that segment. Forelimb upper-arm and forearm frames follow the same proximal-to-distal construction. Pelvis, scapula and trunk have their own assembly frames; consult the frame table below. Local y is an in-plane transverse direction and local z is normal to the limb plane for the limb segment frames. They are not universally world-up or world-left.

pW,k(q)=xB(q)+RB(q)pB,k   (1)

Terms: pB,k is the configured xyz coordinate of point k in body B (m); pW,k is its world coordinate (m); xB is the world position of that body's origin (m); RB is its dimensionless 3×3 rotation matrix; q is the current generalized configuration (translations in m, rotations in rad). The point is constant in its body frame, while xB and RB change during motion. The axes table gives the actual initial orientation for every body.

How does a coordinate edit change MT length?

LMT,i(q)=ci+∑bLpath,ib(q)dib   (2)

Terms: LMT,i is whole muscle–tendon length for muscle path i (m); ci is its configured constant MT_path_length_offset_m (m); b indexes an engine path branch; Lpath,ib is that branch's routed length (m), including straight spans and any surface wrap arcs; dib is the dimensionless branch divisor. All current muscle tendon gears are one. A branch seam is a computational construction, not necessarily a separate biological attachment.

Lstraight=∑k‖pW,k+1−pW,k‖   (3)

Terms: Lstraight is the length (m) of a branch with only straight spans; k indexes successive ordered points and ‖·‖ is Euclidean distance. This formula alone is insufficient when the path wraps: the engine also includes tangent spans and cylinder/sphere surface arcs. A side selector chooses the wrap side and is not included as a mandatory path vertex. Moving it can change the selected path discontinuously.

ΔL≃pO−pI‖pO−pI‖·RBΔpB,O   (4)

Terms: ΔL is the first-order length change (m) for a single straight origin-to-insertion span with insertion held fixed; pO and pI are its world origin and insertion (m); ΔpB,O is the local origin edit (m). Moving directly away from the next path point lengthens a straight span; moving towards it shortens it. A 1 mm edit perpendicular to the span may barely change its length. For a wrapped path or via point use the numerical inspection tool; there is no universal rule that increasing x increases length.

LT=LMT−LFcosα,ϵT=LT−LT0LT0   (5)

Terms: LT is elastic tendon length (m); LF is fibre length (m); α is the fixed pennation angle (rad); LT0 is slack tendon length (m); εT is dimensionless tendon strain. MT length is not fibre length. At the same initial fibre state, a longer MT path stretches the tendon more; subsequent fibre motion and tendon force are solved by the elastic mechanics. The code does not automatically rescale fibre or slack lengths to hide your edit.

Changing the path can also change its angle-dependent length and force moment arms. The native force transmission uses the engine path Jacobian. With computed moving via points, verify it against a finite difference that updates the routing at both perturbed joint positions; geometry edits can spoil virtual-work consistency. A successful coordinate edit is not anatomical or gait validation.

Important editing distinctions

  • Body ownership: editing xyz moves a point within its current body. Attaching it to another bone requires changing model topology, not just its coordinates.
  • Paired seams: some forelimb groups contain multiple computational branches. Keep coincident internal branch endpoints consistent when changing their geometry.
  • Routed muscles: changing an endpoint does not automatically update polar radii/angles in routing.py or wrap surfaces in wrapping.py. Review all three when changing the anatomical routing construction; otherwise you have deliberately created a different approximation.
  • Left/right: configuration entries are independent. Editing R_VL does not silently mirror the change to L_VL. Local-frame signs are not universally the same as world left/right signs.
  • Origins and insertions: names below identify endpoints in the current computational path. Simplified group endpoints are not claims of anatomically exact broad attachment surfaces.
