Experimental data, parameter estimation and forward prediction

A guide to what is measured, what is estimated, and what the simulator computes.

Two procedures have different roles. Offline parameter estimation selected the supplied excitation waveforms and mechanical values. A forward simulation reads those fixed values and predicts motion. It does not compare against measurements to correct its motion while running.

2. Understand how the input is applied

The supplied excitation cycle has period 0.6833333333 s. At each time step the simulator interpolates the saved table at the current cycle time, then repeats it for successive cycles. Muscle, body and contact states continue evolving; they are not reset at cycle boundaries. This is a fixed motor-input model with mechanical coupling, not a sensory-feedback controller.

4. How experimental agreement entered parameter estimation

Calibration used several objectives and tests. The following equation documents the uninterrupted-locomotion objective present in the included method records; it is not an optimizer executed by run.py or a claim that every fitted value was obtained in one search.

J=Jfall+Jangle+JGRF+Jtravel+Jposture+wrhythmJrhythm+30Jphase+Jshape+Jregularization+Jbounds

J is the dimensionless score to minimize. Jfall penalizes falling; Jangle joint-angle error; JGRF ground-reaction-force error; Jtravel forward progress error; Jposture body-posture error; Jrhythm insufficient rhythmic paw contact; Jphase excitation during EMG-quiet phases or insufficient excitation during active phases; Jshape peak-normalized excitation/EMG shape error; Jregularization large fitted-variable changes; and Jbounds fiber-length bound events. wrhythm is the rhythm weight, 2 in the supplied estimation record; the phase weight is 30.

Joint-angle errors were scaled by 8 degrees, anterior–posterior GRF errors by 0.8 N and vertical errors by 2 N before squaring. Regularization was 0.02 times the mean squared fitted variables excluding the waveform-blend variable. The fiber-bound penalty was 0.01 times the fraction of integration steps with a fiber bound. These weights and scales are project calibration choices, not biological constants.

A robustness objective combined 0.5 times the worst trial score and 0.5 times the mean score across nominal and small initial-height/speed perturbations, with identical excitation in every trial. This tests mechanical tolerance without requiring exact equality of successive stride-end states.

The forelimb input estimation also used an offline force-balance adjustment: activation was recalculated along a nominal cycle for chosen muscle properties, regularized over approximately 10 ms, converted to excitation through activation dynamics, and clipped to [0,1]. This adjustment is already represented in the supplied excitation table. It is not applied during a forward run, and does not smooth the predicted GRFs. The adjustment equation and all its terms are defined below.

Offline force-balance adjustment

aB=clip[0,1](aAfL,AfV,A+fPE,A−fPE,B+βAνA−βBνBmax(10−5,fL,BfV,B))

A and B denote two explicitly chosen muscle-parameter sets evaluated along the same nominal cycle during estimation. aA is activation for set A, and aB is the estimated activation for set B. fL and fV are active force–length and force–velocity factors; fPE is passive fiber force divided by the maximum isometric muscle force along the tendon direction; β is normalized fiber damping; ν is fiber lengthening velocity divided by the physical maximum fiber speed. All terms are dimensionless. clip[0,1] bounds activation to [0,1]; the denominator floor 10⁻⁵ prevents division by near-zero active force capacity.

The formula preserves normalized fiber force for the chosen cycle when the same maximum isometric force is used. It is an offline estimate, not a guarantee of unchanged free motion after integration. The saved excitation table contains the result of input estimation; no A-to-B adjustment is evaluated during a normal forward run.

Reproducibility boundary

The supplied input table and parameter dictionaries are the defined starting point of this forward model. The equations above describe their estimation. Running this package reproduces forward predictions from those supplied values; it does not rerun the complete optimization from raw recordings. The verified source values, applied values and parameter-specific rationale are listed in the parameter tables. All required forward-model inputs are included in this repository.

5. Run and inspect the forward calculation

  1. Install the pinned dependencies using the installation instructions.
  2. Inspect the supplied excitation cycle, parameter tables and initial states.
  3. Run python run.py --seconds 60 --no-gui. The solver applies excitation, integrates activation, solves Hill-type muscle dynamics with an elastic tendon, computes paw contact and coupled acceleration, and updates the state continuously.
  4. Inspect the saved kinematics, raw GRFs, activations, forces and moments, and the comparisons with experimental references.

6. What can be reproduced and what remains uncertain

The distributed input tables, model parameters, initial state and code reproduce the supplied forward simulations. The repository does not provide a single command to re-estimate every parameter and excitation from raw recordings. Running a forward prediction and reconstructing parameter estimation are different reproducibility claims.

The intact example sustained the tested 60 seconds. Some joint-angle, vertical-GRF and EMG timing/shape criteria remain unmet. Calibration data are not an independent validation set, and fitting does not uniquely identify muscle properties or neural excitation. See the measured errors and intervention outcomes rather than treating numerical walking as proof of biological validity.
