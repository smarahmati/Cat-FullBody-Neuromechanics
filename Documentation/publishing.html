First publication using GitHub Desktop

  1. In GitHub Desktop, choose File → Add local repository and select this project's root folder, Cat-FullBody-Neuromechanics.
  2. Review the files, enter a commit summary and select Commit to main.
  3. Select Publish repository. Use owner smarahmati and name Cat-FullBody-Neuromechanics. Publish as a public repository for freely accessible code and a GitHub Pages site on GitHub Free.
  4. Open the repository on GitHub. Once only, choose Settings → Pages → Build and deployment → Source → GitHub Actions. The workflow file is already included; no template or additional workflow is needed.
  5. Open Actions → Documentation website. If the first push ran before Pages was enabled, select the failed run and Re-run all jobs, or select Run workflow on the default branch.
  6. After the build and deployment succeed, open the website address above. The deployment also displays its address in the workflow summary.

GitHub requires that one-time repository setting. The included workflow does not require a personal access token or additional secret. Repository or organization policies must allow GitHub Actions and Pages. See GitHub's publishing-source instructions.

After that: edit, commit, push

Save changes, commit them in GitHub Desktop, and select Push origin. Each push to the default main or master branch rebuilds and publishes the documentation. You do not need to upload HTML separately. The workflow checks links before deployment; if the build fails, inspect its error in Actions.

Read the downloaded project

After downloading and extracting the repository, double-click START_HERE.html or index.html. Equations, local figures, the muscle selector and linked guides work without a local server. External papers and GitHub links still require internet access.

Files that control publication and optional local build

The publication workflow runs the website builder, checks links and deploys the static artifact. The builder uses only Python's standard library and Git.

python Code/simulation_tools/build_documentation_website.py --output _site

Run from the project root after committing files. For an uncommitted local preview, add --include-untracked. Choose a new or empty output directory each time. The generated _site directory is ignored by Git. The downloaded source HTML does not require this build.

Workflow design follows GitHub's custom Pages workflow documentation.
