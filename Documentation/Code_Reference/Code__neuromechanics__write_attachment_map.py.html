 162 <h1>Origins, insertions, via points and wrapping</h1>
 163 <p class="note">This is a map of the geometry actually used in the forward simulation. It distinguishes fixed bone/body attachments, moving routing points and wrap surfaces. The visible bone mesh does not automatically determine a muscle path. Some coordinates are registered or estimated model geometry, not measured feline attachment coordinates.</p>
 164 <h2>Which file do I edit?</h2><ul>
 165 <li><code>attachments.py</code>: body-fixed origin/insertion/via coordinates. The named body and role appear immediately above each entry. Metres: <b>0.001 m = 1 mm</b>. Changing a point site's orientation alone does not move its centre or alter MT length.</li>
 166 <li><code>routing.py</code>: geometry parameters of computed moving via points and preferred wrap-side selectors. Their positions are recalculated from joint angles at each step; a static site-coordinate edit would be overwritten.</li>
 167 <li><code>wrapping.py</code>: centres, orientations and radii of the actual sphere/cylinder wrap objects. These are separate from the visible bone surfaces.</li>
 168 <li><code>muscle_tendon.py</code>: constant MT path offset, optimal fibre length and slack tendon length. Changing an attachment does not automatically change these parameters.</li></ul>
 169 <p>Run <code>.\\run_model.ps1 --parameters config/user_model --seconds 3 --output my_attachment_trial</code> from the project folder. A new run rereads the files, applies the values before time zero, and writes an <code>ATTACHMENT_MAP.html</code> and <code>APPLIED_PARAMETERS.json</code>. Edits are not silently refitted. Use a new output name for each trial.</p>
 170 <h2>Where are these coordinates?</h2>
 171 <p>A local coordinate belongs to the named rigid body, not the world and not the bone mesh file. In a hindlimb thigh frame, zero is the hip centre and +x runs along the segment towards the knee. In shank and foot frames, zero is their proximal joint and +x points along that segment. Forelimb upper-arm and forearm frames follow the same proximal-to-distal construction. Pelvis, scapula and trunk have their own assembly frames; consult the frame table below. Local y is an in-plane transverse direction and local z is normal to the limb plane for the limb segment frames. They are <em>not</em> universally world-up or world-left.</p>
 172 <div class="equation">p<sub>W,k</sub>(q) = x<sub>B</sub>(q) + R<sub>B</sub>(q) p<sub>B,k</sub> &nbsp; (1)</div>
 173 <p><b>Terms:</b> p<sub>B,k</sub> is the configured xyz coordinate of point k in body B (m); p<sub>W,k</sub> is its world coordinate (m); x<sub>B</sub> is the world position of that body's origin (m); R<sub>B</sub> is its dimensionless 3×3 rotation matrix; q is the current generalized configuration (translations in m, rotations in rad). The point is constant in its body frame, while x<sub>B</sub> and R<sub>B</sub> change during motion. The axes table gives the actual initial orientation for every body.</p>
 174 <h2>How does a coordinate edit change MT length?</h2>
 175 <div class="equation">L<sub>MT,i</sub>(q) = c<sub>i</sub> + ∑<sub>b</sub> L<sub>path,ib</sub>(q) / d<sub>ib</sub> &nbsp; (2)</div>
 176 <p><b>Terms:</b> L<sub>MT,i</sub> is whole muscle–tendon length for muscle path i (m); c<sub>i</sub> is its configured constant <code>MT_path_length_offset_m</code> (m); b indexes an engine path branch; L<sub>path,ib</sub> is that branch's routed length (m), including straight spans and any surface wrap arcs; d<sub>ib</sub> is the dimensionless branch divisor. All current muscle tendon gears are one. A branch seam is a computational construction, not necessarily a separate biological attachment.</p>
 177 <div class="equation">L<sub>straight</sub> = ∑<sub>k</sub> ‖p<sub>W,k+1</sub> − p<sub>W,k</sub>‖ &nbsp; (3)</div>
 178 <p><b>Terms:</b> L<sub>straight</sub> is the length (m) of a branch with only straight spans; k indexes successive ordered points and ‖·‖ is Euclidean distance. This formula alone is insufficient when the path wraps: the engine also includes tangent spans and cylinder/sphere surface arcs. A side selector chooses the wrap side and is not included as a mandatory path vertex. Moving it can change the selected path discontinuously.</p>
 179 <div class="equation">ΔL ≈ [(p<sub>O</sub> − p<sub>I</sub>)/‖p<sub>O</sub> − p<sub>I</sub>‖] · R<sub>B</sub> Δp<sub>B,O</sub> &nbsp; (4)</div>
 180 <p><b>Terms:</b> ΔL is the first-order length change (m) for a single straight origin-to-insertion span with insertion held fixed; p<sub>O</sub> and p<sub>I</sub> are its world origin and insertion (m); Δp<sub>B,O</sub> is the local origin edit (m). Moving directly away from the next path point lengthens a straight span; moving towards it shortens it. A 1 mm edit perpendicular to the span may barely change its length. For a wrapped path or via point use the numerical inspection tool; there is no universal rule that increasing x increases length.</p>
 181 <div class="equation">L<sub>T</sub> = L<sub>MT</sub> − L<sub>F</sub> cos α, &nbsp; ε<sub>T</sub> = (L<sub>T</sub> − L<sub>T0</sub>)/L<sub>T0</sub> &nbsp; (5)</div>
 182 <p><b>Terms:</b> L<sub>T</sub> is elastic tendon length (m); L<sub>F</sub> is fibre length (m); α is the fixed pennation angle (rad); L<sub>T0</sub> is slack tendon length (m); ε<sub>T</sub> is dimensionless tendon strain. MT length is <b>not</b> fibre length. At the same initial fibre state, a longer MT path stretches the tendon more; subsequent fibre motion and tendon force are solved by the elastic mechanics. The code does not automatically rescale fibre or slack lengths to hide your edit.</p>
 183 <p>Changing the path can also change its angle-dependent length and force moment arms. The native force transmission uses the engine path Jacobian. With computed moving via points, verify it against a finite difference that updates the routing at both perturbed joint positions; geometry edits can spoil virtual-work consistency. A successful coordinate edit is not anatomical or gait validation.</p>
 184 <h2>Important editing distinctions</h2><ul><li><b>Body ownership:</b> editing xyz moves a point within its current body. Attaching it to another bone requires changing model topology, not just its coordinates.</li><li><b>Paired seams:</b> some forelimb groups contain multiple computational branches. Keep coincident internal branch endpoints consistent when changing their geometry.</li><li><b>Routed muscles:</b> changing an endpoint does not automatically update polar radii/angles in <code>routing.py</code> or wrap surfaces in <code>wrapping.py</code>. Review all three when changing the anatomical routing construction; otherwise you have deliberately created a different approximation.</li><li><b>Left/right:</b> configuration entries are independent. Editing R_VL does not silently mirror the change to L_VL. Local-frame signs are not universally the same as world left/right signs.</li><li><b>Origins and insertions:</b> names below identify endpoints in the current computational path. Simplified group endpoints are not claims of anatomically exact broad attachment surfaces.</li></ul>
 185 <h2>All muscle paths</h2><p>Search by muscle, body or point name. L/R = left/right hindlimb; FL/FR = left/right forelimb. SAM is the existing medial sartorius/SRTm model-channel label. Coordinates shown here are read back from the engine at the listed pose.</p>
